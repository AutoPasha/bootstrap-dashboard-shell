# Dashboard Shell на Bootstrap 5

[![tests](https://github.com/AutoPasha/bootstrap-dashboard-shell/actions/workflows/tests.yml/badge.svg)](https://github.com/AutoPasha/bootstrap-dashboard-shell/actions/workflows/tests.yml)

Живая страница: https://autopasha.github.io/bootstrap-dashboard-shell/

Оболочка кабинета без сборки: ES-модули и Bootstrap 5.3.8 из `vendor/`. Меню, Offcanvas, крошки и заголовки строятся из одного реестра маршрутов. Рабочий контекст хранится в одном сторе оболочки.

## Как реестр становится меню, Offcanvas и крошками

- `src/routes.js` - реестр. У каждой строки `path`, `title`, `parent`, `section`, `icon`, по желанию `only` (в каких видах контекста страница имеет смысл).
- `buildNav(registry, context)` в `src/nav.js` собирает модель меню: разделы и пункты в порядке реестра, счетчики берутся из контекста, страницы без смысла в нем пропускаются.
- `renderNav` в `src/shell.js` рисует эту модель в одну разметку с классом `.offcanvas-lg`. От 992px это колонка sidebar, на экранах уже это Offcanvas. Второго меню в DOM нет, разъехаться пунктам негде.
- `breadcrumbs(registry, path)` идет по цепочке `parent`: Главная › Профиль › Безопасность. Последняя крошка без ссылки и с `aria-current="page"`.
- Новая страница = строка в реестре и функция в `src/pages.js`. Меню, крошки, `document.title` и тесты подхватят ее сами.

## Где контекст

- `src/store.js`: стор оболочки хранит `contextId` (в sessionStorage, чтобы пережить перезагрузку). Меню и страницы его читают и подписываются на изменения.
- Адреса от контекста не меняются. Меняются подписи (пространство, роль), счетчики в меню и данные страниц.
- Если открытая страница теряет смысл в новом контексте (настройки команды в личном пространстве), оболочка уводит на `/app/overview`, заменяя запись в истории, и сообщает об этом через `aria-live`.
- Оболочка одна на все роли: роль приходит вместе с контекстом как данные, своей разметки под роль нет.

## Клавиатура и фокус

- Skip-link ловится первым Tab и ставит фокус на h1, hash-маршрут при этом не меняется.
- `aria-current="page"` стоит на активном пункте меню и на последней крошке.
- После перехода фокус переезжает на h1 новой страницы. При первой загрузке фокус остается на месте.
- Offcanvas открывается с фокусом на текущем пункте. Esc закрывает меню и возвращает фокус на кнопку, переход по пункту закрывает меню и ставит фокус на h1.

## Тесты

- `npm run test:unit` проверяет реестр, `buildNav` и `breadcrumbs` в node, без браузера.
- `npx playwright test` гоняет матрицу: 6 маршрутов × chromium, firefox, webkit × 6 ширин (320, 375, 768, 991, 992, 1440), всего 108 прогонов. В каждом проверяются h1 и title, единственный пункт с `aria-current`, крошки, отсутствие прокрутки вбок, skip-link, меню с клавиатуры и фокус на h1 после перехода. Отдельно 24 сценария контекста.
- Таблица матрицы попадает в итоги прогона Actions. Pages выкатывается только после зеленой матрицы.

```bash
npm ci
npm start
npx playwright install chromium firefox webkit
npm test
```

## Почему маршрут в hash

GitHub Pages отдает статику и не умеет переписывать адреса, поэтому маршрут живет в `#/app/...`. В приложении с сервером реестр, `nav.js` и тесты остаются как есть, меняются две функции в `shell.js`: `pathFromHash` и `go`.
